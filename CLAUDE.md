# FPM Teaching App — working notes

Interactive teaching tool for **Fourier ptychographic microscopy (FPM)**, aimed
at undergraduates who will build/operate a 3D-printed FPM. Built with
[marimo](https://marimo.io); runs fully client-side via WASM (Pyodide) on GitHub
Pages. Full design intent lives in `fpm_teaching_app_spec.md` — read it before
making pedagogical changes.

## The fast iteration loop (read this first)

Everything routes through `dev.py`:

| Command | What it does | When |
| --- | --- | --- |
| `python dev.py edit` | Live **reactive notebook** editor | Editing code *or* prose — the primary loop. Changes apply instantly. |
| `python dev.py preview` | Serves the app in **run mode** locally (what students see), backed by a real Python kernel | Checking the polished app layout, fast. |
| `python dev.py check` | Compile + marimo dependency-graph load | Quick correctness gate; also runs in CI. |
| `python dev.py build` | Static WASM export to `dist/` | Sanity-checking the exact Pages artifact. |
| `python dev.py serve` | `build` + local http server | Reproducing the real Pyodide cold-load. |
| `python dev.py deploy "msg"` | Commit + push to `web` → CI → Pages | Publishing. |

Key point: **`edit` and `preview` use a local kernel, so iteration is instant** —
you do *not* pay the WASM cold-load while working. Only `build`/`serve` exercise
Pyodide, and only the public URL needs a `deploy`.

## Deploy

Pushing to the **`web`** branch triggers `.github/workflows/deploy.yml`:
pinned `pip install` → `python dev.py check` → `marimo export html-wasm` → Pages.
`dist/` is git-ignored and regenerated by CI — never commit it. Dependency
versions are pinned in the workflow; bump them deliberately when you upgrade
locally (keep them in sync with your machine).

## Architecture of `app.py`

A single marimo notebook = a list of `@app.cell` functions. A cell's inputs are
its function arguments; marimo derives the dependency graph from the **cell
body** (names used vs. defined), not the signature, and reruns only what a change
affects. That's why editing is cheap.

**Display rule (important):** a cell renders only its **last bare expression**.
The whole UI is assembled once in the final `_tabs` cell via `mo.ui.tabs(...)`;
every other cell therefore ends with an assignment/`return` and shows *nothing*
inline. If you add a widget cell, do **not** leave a trailing bare expression, or
it will render twice (once inline, once in the tab) — the exact "duplicated
simulations" bug that was fixed. Compose new content into the relevant
`tabN`/`_tab..._assembly` cell instead.

### Shared infrastructure (top of file, reuse everywhere)
- `_fft_utils`: `ft`/`ift` (centered FFT convention — see module docstring; one
  flipped axis here is the classic silent bug), `make_pupil`, `na_to_cutoff_px`,
  and the single forward model `simulate_intensity(object, pupil, k_shift_px)`.
- `_plotting`: `two_pane` / `three_pane` (real-space left, Fourier right; phase is
  alpha-masked by magnitude; pupil drawn as a cyan circle) and **`show_fig(fig)`** —
  wrap every matplotlib figure in this. It renders a *static PNG* (much lighter
  than `mo.mpl.interactive` in WASM) and calls `plt.close(fig)` to avoid a
  per-interaction figure leak. **Never use `mo.mpl.interactive`** here.
- `_object_library`, `_zernike`: presets and aberration phase maps.

### Tab layout
Each tab = controls cell(s) + plot cell(s) + prose cell(s), gathered by a
`_tabN_assembly` cell. Grids: **256²** for the live Tabs 1–3, **128²** for the
Tab 4/5 reconstruction (keeps the iterative loop responsive).

The five tabs own distinct ideas — keep them distinct: Tab 3 = *more angles →
more resolution* (bandwidth), **Tab 4 = *overlap → phase → resolution*** (why
phase retrieval is possible at all), Tab 5 = *does it survive real noise /
aberration* (practice).

### Tab 4 — "Why overlap buys resolution" (stateless / reactive)
Rebuilt to teach the phase-retrieval insight, not to be another reconstruction
stepper. One slider (`t4_nside`, LEDs across a fixed-aperture array) drives
everything reactively — **no `mo.state`, no buttons** (the old click-counter
stepper is gone). Pipeline of pure cells: `_t4_config` (geometry constants
`T4_*`) → `_t4_target` (a **compact mixed object**: a Siemens star in
*amplitude* = the resolution target, plus a rotated star in *phase* = the hard,
hidden channel) → `_t4_setup` (LED grid, overlap %, noisy measurements, k-space
redundancy map, constraint counts) → `_t4_recon` (alternating-projection
recovery, reruns on slider change) → `_t4_why_plot` (redundancy map +
measurements-vs-unknowns bar; phase doubles the unknowns, overlap supplies them)
→ `_t4_payoff_plot` (2×3: amplitude/phase rows × ground-truth / FPM-recovered /
conventional-microscope columns; phase is alpha-masked by magnitude) →
`_t4_assembly`. Physics is tuned (`R_OBJ=11`, `R_SYNTH=37`, `~10` iters, mild
shot noise) so **amplitude resolves ~50% overlap while phase visibly lags and
only settles ~60%** — the honest point that "more knowns than unknowns" is
necessary but *not* sufficient (phase retrieval is nonconvex; overlap must buy
stability, not just coverage). The counting panel is framed as a floor, not a
promise. Reuses the shared `simulate_intensity`/`ft`/`ift`/`make_pupil`. Note
`_t4_groundtruth` (`make_ground_truth`) and `_t4_geometry` (`PUPIL_CUTOFF_PX`,
`LED_GRID_SIDE`) sit just above and are **shared with Tab 5** — don't delete them.

Gotcha: `marimo export html` (the non-WASM static snapshot) can silently reuse a
stale `__marimo__/session/*.json` cache and emit a code-only file with no
figures. It's git-ignored and irrelevant to deploy (CI runs fresh; WASM renders
in-browser); if a local snapshot looks empty, delete `__marimo__/session` and
re-export, or just use `python dev.py preview`.

## Conventions
- numpy + matplotlib only (no scipy) to keep the WASM bundle small and cold-load fast.
- One FFT sign/orientation convention, documented once in the `app.py` docstring.
- Prose lives in `mo.md(...)` inside the relevant cell, co-located with its widget.
